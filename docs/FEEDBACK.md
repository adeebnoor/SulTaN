# Give useful feedback

Try the fictional example or use non-sensitive planning data. Change a choice or weight, connect an enabler or initiative, and export a draft. Then use **Share feedback**.

For a bug, describe what you tried, what you expected, what occurred, and the shortest reproduction steps. Mention Arabic/English and desktop/mobile when relevant. Do not attach your strategy, contact details of other people, employee records, unpublished targets, or screenshots containing sensitive information.

The email option prepares a draft in your mail application; you send it there. The GitHub option opens a public draft and requires an account and a separate submission on GitHub. Copying a draft does not send it. The interface states these distinctions explicitly.

Repository templates and maintainer-facing documentation are in English. Arabic feedback is welcome by email. Translating user-entered content automatically is not part of the beta.

Suggested categories: usability, language, reference/roadmap workflow, calculation, export/import, accessibility, and improvement ideas. A reproducing example with fictional data is more useful than a confidential project file.
